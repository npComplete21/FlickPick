# 01 – Tooling: Maven Wrapper & Node

**Date:** 2026-08-05

## Maven: using the wrapper (mvnw), no global install
Each Spring Boot service ships its own `mvnw`/`mvnw.cmd` + `.mvn/wrapper/`,
generated by Spring Initializr. Running `./mvnw ...` downloads the exact
Maven version pinned for that project (once, cached in
`~/.m2/wrapper/dists/`) and uses it — no system-wide Maven needed beyond the
Java 21 already installed.

**Why:** the Maven version is pinned per-project instead of per-machine, so
all three services build reproducibly regardless of what's globally
installed, and there's zero setup step for anyone cloning the repo.

**Trade-offs accepted:** first run needs network access to fetch that Maven
version; a few extra files (`mvnw`, `mvnw.cmd`, `.mvn/`) committed per
service; upgrading Maven later is a per-project edit instead of one global
upgrade.

## Node: installed globally via Homebrew
Ran `brew install node` → Node v26.6.0, npm 11.18.0, both on PATH via
`/opt/homebrew/bin`.

**Why:** our frontend tooling (Vite, npm) is itself JavaScript, which needs a
runtime to execute outside the browser. Unlike Maven, there's no wrapper
option — Node is the runtime itself, not a project dependency, so it has to
actually exist on the machine.
